## 2. 데이터 구조 (MongoDB 컬렉션)

### `users` — 사용자
| 필드 | 설명 |
|---|---|
| email, passwordHash | 로그인 정보 (비밀번호는 암호화해서 저장) |
| name, schoolName | 교사 이름, 학교명 (활동명 중복 검사에 사용) |
| role | `teacher` / `admin` |
| status | `active` / `pending`(가입 승인 대기) / `blocked` |
| createdAt, lastLoginAt | |

### `designs` — 설계 문서 (핵심)
| 필드 | 설명 |
|---|---|
| ownerId | 작성자 |
| type | `subject`(과목) / `activity`(활동) |
| status | `draft`(작성 중) / `completed`(완성) |
| currentStep | 위저드 어느 단계까지 했는지 |
| basic | 학교명, 학년도, 학년, 학기, 운영 시수, 편성 교과(군), 개설 형태, 운영 방식, 이름(한글/영문) |
| input | 주제, 필수 내용[], 원하는 활동[], 학교·지역 여건, 연계 자원(마을학교·체험처 등) |
| aiCandidates | AI가 제안한 지도계획 3안 (원본 보관) |
| selectedCandidate | 선택한 안 번호 |
| doc | 최종 문서 본문: 성격/필요성, 목표(총괄+세부3), 내용 체계(핵심아이디어·영역·내용 요소), 성취기준[], 교수·학습/평가 방향·방법, 단원 지도계획[], 평가 계획[], 신청서 항목(교재, 지도교사 확보 방안 등) |
| checklist | 서식6/7 체크리스트 교사 확인 결과 |
| validation | 마지막 검증 결과 (오류·경고 목록, 검사 시각) |
| createdAt, updatedAt | |

### `designVersions` — 저장할 때마다 이전 버전 보관 (되돌리기용)

### `nationalStandards` — 2022 개정 국가 성취기준 (data/ JSON을 DB로 불러온 것)
| code, subject, gradeBand, area, text |

### `promptLogs` — 프롬프트 사용·답 읽기 기록 (관리자 모드용)
| userId, designId, kind(지도계획/성취기준/문장), 답 읽기 성공 여부, 실패 이유, createdAt |
※ 앱은 AI를 직접 부르지 않으므로 비용·토큰 기록은 없음. 프롬프트·답 원문은 저장하지 않음 (개인정보 방지)

### `activityLogs` — 로그인·저장·다운로드 등 이용 기록 (관리자 모드용)

## 4. 단계별 작업 계획

| 단계 | 내용 | 끝나면 확인할 것 |

## 사용자 결정 메모 (2026-10-30)

- **로그인하지 않은 체험**: 설계·시수 점검은 할 수 있지만 이 브라우저에만 임시 저장되고 문서(.docx)는 내려받을 수 없다.
  첫 화면·상단의 '새 설계'·'시수 점검'을 누르면 경고 팝업(✕ / 체험하기 / 로그인)을 띄우고, 설계·시수 점검 화면 위에는 빨간 경고 줄을 둔다.
- **AI 없이 직접 입력하기**: 'AI에게 초안 받기' 옆 버튼으로 단계별 빈칸 틀을 만든다 (`src/domain/manual.ts`).
- **AI 답 반영 후 경고 팝업**: 사실과 다른 내용, 문법·맞춤법, 지침·성취기준 불일치, 학교 실정, 저작권·치우친 관점을 반드시 직접 점검하라고 알린다.

## 사용자 결정 메모 (2026-10-31)

- **되돌리기·다시 실행**: 설계 전체(단계를 넘어도), 최근 100번, 1초 안의 연속 입력은 한 번으로. 페이지를 새로 열면 기록은 사라진다.
- **설계 화면 위 '문서' 버튼**: 설계 현황과 같은 조건(오류 0개 + 체크리스트 모두 ○ + 로그인)일 때 내려받기, 아니면 남은 것을 알려 주고 점검 단계로 안내.
- **운영 시수 경고**: 같은 학년도·학년·학기의 다른 설계와 합쳐서 판단한다 (17차시 설계가 있으면 12차시 설계에는 경고 없음).
- **.docx 쪽 나눔 (AI 없이 규칙으로)**:
  - 1(필요성·목표)과 2(내용 체계)가 한 쪽에 조금 넘치면 줄 간격을 줄여 한 쪽에, 그래도 안 되면 내용 체계를 통째로 다음 쪽으로.
  - 성취기준·평가 계획은 한 쪽에 들어가면 통째로 한 쪽에. 평가 계획의 한 시기(성취기준 + A·B·C)는 쪽에서 나뉘지 않음.
  - 단원 지도계획은 차시 한 줄 단위로 넘어가고, 합친 단원명·성취기준 칸의 글이 잘리지 않도록 그 글 높이만큼의 차시 줄은 묶어서 넘긴다.
  - 높이는 글자 수로 어림한다 (`src/export/layout.ts`).

## 사용자 결정 메모 (2026-10-31, 관리자·예시안)

- 예시안: 관리자가 '예시안' 탭에서 파일(hwp·hwpx·docx·pdf, 4MB 이하)을 올리고, 첫 화면에서 로그인 없이 누구나 내려받는다.
- 관리자 대시보드: 가입 학교·설계 완성·설계 중 3상자 (누르면 해당 목록).
- 계정 삭제: 그 학교의 설계·시수 점검도 함께 삭제 (이용 기록은 남김).
- 관리자 '상세보기'·'시수점검': 그 학교로 들어가 학교가 보는 화면 그대로 보고 고침. 고친 것은 이용 기록에 '관리자 작업'으로.
- 관리자 표 정렬 세모: 기본 검은 ▼ → 파란 ▼(오름차순) → 빨간 ▲(내림차순) → 기본. 관리자 모드의 모든 목록 표에 적용.
- '확인 필요'(권장) 점검 무시하기: 설계마다 기억, 내용이 바뀌어 문장이 달라지면 다시 표시, 오류는 무시 불가.
- 성취기준 약어: 꼭 입력 (비면 다음 막기). 내용 요소는 성취기준마다 고르게 (프롬프트 강제 + 4개 이상이면 안내).
- 단원 지도계획: n번째 단원 = n번째 영역의 성취기준 (고르지 않음).
- 이용 기록: 화면에는 최근 30개 + 더 보기 + 전체 목록 조회, DB에서는 1년 지나면 자동 삭제.

## 사용자 결정 메모 (2026-10-31, 엑셀)

- 학교 일괄 등록: 관리자 사용학교 탭에서 엑셀 양식(지역 드롭다운·학교명·비밀번호) 내려받기 → 끌어다 놓기(또는 고르기)로 올림 → 미리보기 → 등록. 개별 추가도 가능. 등록하면 바로 '사용 중'. 비밀번호는 엑셀에 적은 값.
- 편성표 엑셀(.xlsx): .docx와 같은 모양. 노란 칸(학기별 편성 시수·학교자율시간)을 바꾸면 증감·계·소계·학년군 합계·연간 수업 시간 수·판정이 수식으로 다시 계산 (`src/export/allocationXlsx.ts`).
- 엑셀 라이브러리 exceljs는 내려받기·올리기할 때만 화면에서 불러온다.
